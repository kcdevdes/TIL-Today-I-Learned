# PostgreSQL

## Postgres.app
- A macOS app that **installs and runs a local PostgreSQL server** on my Mac (it is not a client itself).
- It also bundles CLI tools such as `psql`, the default command-line **client**.
- Client vs server:
  - Server: stores the data and executes queries (started by Postgres.app, default port `5432`).
  - Client: connects to the server and sends SQL (`psql`, pgAdmin, DBeaver, TablePlus, a Spring Boot app via JDBC).

```bash
# Connect to a database with psql
psql -U postgres -d postgres
```

## psql Meta-Commands
- Commands that start with `\` are **psql meta-commands**, not SQL. They do not need a `;`.

| Command | Meaning | Example |
| --- | --- | --- |
| `\?` | Help for psql meta-commands | `\?` |
| `\h` (`\help`) | Help for **SQL** commands | `\h CREATE TABLE` |
| `\q` | Quit psql | `\q` |
| `\l` | List databases | `\l` |
| `\c` | **Connect** to another database | `\c mes_study` |
| `\d` | **Describe**: list tables/views/sequences | `\d` |
| `\d <table>` | Show columns, types, constraints of a table | `\d equipment` |
| `\dt` | List tables only | `\dt` |

- Note: `\c` switches the **database**, not a table. Tables are queried with SQL, not "entered".

## Basic SQL
- SQL statements must end with `;`. Without it, psql waits for more input (prompt changes from `=#` to `-#`).

### CREATE DATABASE
```sql
CREATE DATABASE mes_study;
```
```
\c mes_study
```

### CREATE TABLE
- Syntax: `CREATE TABLE <table_name> (<column_name> <type> [constraints], ...);`
- Columns are separated by commas.

```sql
CREATE TABLE equipment (
    id             BIGSERIAL     PRIMARY KEY,
    equipment_code VARCHAR(50)   NOT NULL UNIQUE,
    name           VARCHAR(100)  NOT NULL,
    status         VARCHAR(20)   NOT NULL DEFAULT 'IDLE',
    description    TEXT,                          -- nullable (no constraint)
    created_at     TIMESTAMPTZ   NOT NULL DEFAULT now()
);
```

```sql
INSERT INTO equipment (equipment_code, name)
VALUES ('EQ-COATER-01', 'Coater #1');

SELECT * FROM equipment;
```

### Constraints
- **Columns are nullable by default.** Writing `NULL` explicitly is allowed but usually unnecessary.
- If a value must always exist, declare `NOT NULL`.

| Constraint | Meaning |
| --- | --- |
| `NOT NULL` | Value is required |
| `PRIMARY KEY` | Unique + NOT NULL; identifies a row |
| `UNIQUE` | No duplicate values (NULLs are allowed, and multiple NULLs do not conflict) |
| `DEFAULT <value>` | Value used when the column is omitted in INSERT |
| `CHECK (<condition>)` | Value must satisfy a condition |
| `REFERENCES <table>(<column>)` | Foreign key to another table |

```sql
-- This fails: name is NOT NULL
INSERT INTO equipment (equipment_code) VALUES ('EQ-PRESS-01');
-- ERROR: null value in column "name" ... violates not-null constraint

-- This fails: equipment_code is UNIQUE
INSERT INTO equipment (equipment_code, name) VALUES ('EQ-COATER-01', 'Duplicate');
-- ERROR: duplicate key value violates unique constraint ...
```

- Why it matters: constraints protect data integrity at the DB level, even if application code has a bug
  (e.g., the same equipment registered twice).
