### Key Concepts
- `spring-boot-starter-jdbc` → auto-configuration creates a `DataSource` bean (HikariCP pool). Without `spring.datasource.url`, the app fails **at startup**, because beans are created when the context starts.
- **Connection success ≠ correct schema.** The pool only proves login works; a wrong DB still fails later on the first query (`relation "equipment" does not exist`).
- Postgres.app: `psql` without options connects to the DB named after the macOS user (`gchoi`). That's why yesterday's tables were in `gchoi`, not `postgres`.
- Empty password works only because `pg_hba.conf` uses `trust` for localhost (no password check at all).
- Never put real passwords in a committed file → use env vars like `${DB_PASSWORD}`.
- Both `postgres` and `gchoi` are superusers. Real apps should use a dedicated role with least privilege.
